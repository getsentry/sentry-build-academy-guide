Follow this guide to get the OpenTelemetry E-commerce application running on your local machine. This is the application we'll use throughout the workshop to learn how to send OpenTelemetry data to Sentry.

## Prerequisites

Before you begin, ensure you have the following:

- [Git](https://git-scm.com/downloads)
- [Node.js](https://nodejs.org/) (version 18 or higher)
- [Free Neon account](https://neon.tech/) (for PostgreSQL database)
- [Free Sentry account](https://sentry.io/signup/) with OTLP enabled
  - Create a **new project** in Sentry (any platform type works - we'll configure OTLP manually)

:::tip[About the Demo Application]
This is a full-stack e-commerce application with:
- **Backend**: Node.js + Express with OpenTelemetry instrumentation
- **Frontend**: React with Sentry SDK
- **Database**: Neon PostgreSQL with product catalog and orders
- **Payment Simulation**: Realistic payment flow with random failures

We'll use this app to demonstrate how OpenTelemetry data flows into Sentry and how to debug real-world issues.
:::

## Setup Instructions

<Steps>
  1. **Clone the repository**

     ```bash
     git clone https://github.com/jaffrepaul/otel-ecommerce
     cd otel-ecommerce
     ```

  2. **Set up the Backend API**

     Navigate to the API directory and install dependencies:

     ```bash
     cd api
     npm install
     ```

  3. **Create Neon Database**

     Create a Neon PostgreSQL database with interactive setup:

     ```bash
     npx neondb -y
     ```

     This will create a new Neon database and automatically configure your `DATABASE_URL` environment variable.

  4. **Configure Environment Variables**

     Copy the environment file:

     ```bash
     cp .env.example .env
     ```

     Edit the `.env` file to add:
     - Your Neon `DATABASE_URL` (should be automatically set by `npx neondb`)
     - Sentry OTLP endpoints (host and authentication token)

     We'll configure the Sentry endpoints in detail in the next module.

  5. **Initialize the Database**

     Create the database schema and seed it with product data:

     ```bash
     npm run db:setup
     ```

     You should see:
     ```
     ✅ Schema created successfully
     ✅ Database seeded successfully
     ✨ Database setup complete!
     ```

  6. **Set up the Frontend**

     Open a new terminal window, navigate to the frontend directory:

     ```bash
     cd ../frontend
     npm install
     cp .env.example .env
     ```

     We'll configure the Sentry SDK settings in the next module.

  7. **Verify Setup**

     At this point, you should have:
     - Neon PostgreSQL database created and configured
     - Backend ready to start (we'll do this after configuring Sentry)
     - Frontend ready to start
</Steps>

## Application Features

The e-commerce app includes:

### Backend API Endpoints
- `GET /api/products` - List all products
- `GET /api/products/:id` - Get product details
- `POST /api/orders` - Create an order
- `GET /api/orders/:id` - Get order details

### Frontend Pages
- **Product List** - Browse all available products
- **Product Detail** - View individual product information
- **Shopping Cart** - Add/remove items
- **Checkout** - Place orders with payment processing

### Built-in Error Scenarios
The application includes realistic error scenarios for testing:
- Payment failures (10% random failure rate)
- Inventory conflicts (insufficient stock)
- Validation errors (invalid input)
- Database query failures

These will be useful when we explore debugging with distributed tracing later in the workshop.

## Common Issues

**"npx neondb command failed"**
→ Make sure you have a Neon account at https://neon.tech/ and are logged in. You may need to authenticate first.

**"Database connection error"**
→ Check that your `DATABASE_URL` in `api/.env` is correctly set to your Neon database connection string.

**"Port 3000 already in use"**
→ Another application is using port 3000. Stop it or change `PORT=3001` in `api/.env`

**"npm run db:setup fails"**
→ Verify your Neon database connection by checking the `DATABASE_URL` environment variable. Make sure the database is accessible.
